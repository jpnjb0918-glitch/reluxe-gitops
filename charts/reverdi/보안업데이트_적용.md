## 🔴 왜 환경별로 달라야 하나

### `TRUST_PROXY_HEADERS`

`app/ratelimit.py` 주석이 상황을 설명합니다.

> ALB 뒤에서는 `request.client.host` 가 전부 ALB 의 IP 라, 그것으로 세면
> **모든 사용자가 한 사람으로 묶여 첫 사용자가 상한을 채우면 전원이 막힌다.**
>
> 로컬에서는 이 헤더를 믿으면 안 된다 — 누구나 헤더에 아무 IP 나 적어서 제한을 피할 수 있다.

| 환경 | 값 | 이유 |
|---|---|---|
| Vagrant | `false` | NodePort 로 직접 들어온다. 프록시가 없다 |
| AWS | `true` | ALB 가 X-Forwarded-For 를 붙인다 |

### `DATABASE_SSL_MODE`

기본값 `prefer` 는 **"되면 쓰고 안 되면 평문"** 입니다.
앱은 운영에서 경고만 남기고 기동하므로, 우리가 값을 줘야 합니다.

```python
if IS_PRODUCTION and DATABASE_SSL_MODE in ("disable", "allow", "prefer"):
    logger.warning("DATABASE_SSL_MODE=%s 로 운영 기동 — DB 연결이 평문일 수 있습니다.")
```

| 환경 | 값 |
|---|---|
| Vagrant | `prefer` — CloudNativePG 가 TLS 를 자동 구성하나 검증은 불필요 |
| AWS | **`require`** — VPC 안이라도 평문은 두지 않는다 |

## ⚠️ 남은 과제 (AWS 이관 시)

### ① 속도 제한이 파드 메모리에 있다

`app/ratelimit.py` 는 **프로세스 안에서** 셉니다.

| | |
|---|---|
| 로그인 잠금 5회 | 파드 3개면 **실질 15회** |
| 파드 재시작 | 카운터 **초기화** |

백엔드도 알고 있고, 해법으로 **AWS WAF rate-based rule** 을 지목했습니다.

> 파드를 가로지르는 제한은 앞단의 WAF rate-based rule 몫이고,
> 이 모듈은 WAF 가 없을 때의 최소 방어선이다.

**C 담당** — AWS 이관 시 WAF 웹 ACL 검토 (월 $5 + 규칙당 $1)

### ② 🔴 X-Forwarded-For 첫 값을 쓴다

```python
first = forwarded.split(",", 1)[0].strip()
```

**ALB 기본 동작은 클라이언트가 보낸 XFF 뒤에 실제 IP 를 append** 하는 것입니다.

```
클라이언트가 보냄:  X-Forwarded-For: 1.2.3.4
ALB 통과 후:        X-Forwarded-For: 1.2.3.4, <실제IP>
                                     ↑ 앱이 이걸 쓴다 — 조작 가능
```

**대응** — ALB 속성을 바꿔 헤더를 덮어쓰게 합니다.

```
routing.http.xff_header_processing.mode = replace
```

Terraform 또는 Ingress 어노테이션으로 설정합니다. **C 담당**

> 백엔드에도 알려주는 게 좋습니다. 코드 주석에 "앞에 프록시가 있어서 헤더를
> 덮어쓰는 것이 보장될 때만 켠다" 고 되어 있는데, ALB 기본은 덮어쓰기가 아닙니다.

### ③ RDS 루트 CA 번들 (선택)

`verify-full` 로 올리려면 필요합니다. `require` 만으로도 전송 구간은 암호화되므로
**우선순위는 낮습니다.**

```bash
curl -o rds-ca.pem https://truststore.pki.rds.amazonaws.com/ap-northeast-2/ap-northeast-2-bundle.pem
kubectl create configmap rds-ca -n reverdi --from-file=rds-ca.pem
```

`deployment.yaml` 에 볼륨 마운트를 추가하고 `DATABASE_SSL_ROOT_CERT` 에 경로를 줍니다.
**A + C 협의 필요**
